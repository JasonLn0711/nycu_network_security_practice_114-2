摘要
本專案實作一個 bounded autonomous exploit agent，用於作業提供的 Docker lab 環境。系統由 External Container 中的 /exploit、/triage 與 analyze_target.py 組成，透過共享目錄 /shared 與 Internal Container 中的 blogic 互動。
本系統不是泛用型外部攻擊工具，而是限制在作業環境中的自動化漏洞分析與利用代理。它會先分析 /shared/blogic 或 /shared/blogic.copy，辨識 ELF 保護機制、symbol table、可疑字串、risky imports 與 ret gadget，再根據分析結果產生 /shared/config.data 並建立 /shared/exploit_done。
系統支援兩種展示模式：Fast Mode 用於正式 grading，追求最短成功時間；Adaptive Offset Probing Mode 則展示 agent 在最多 60 rounds 的限制內自動嘗試 return-address offset candidate，並在第 6 輪找到有效 offset 104 後成功觸發 /backdoor。
1. 作業需求與本系統對應
根據作業說明，學生需要準備 External Container，並確保 /exploit 與 /triage 兩個程式位於正確路徑且可執行。/exploit 必須修改 /shared/config.data 並建立 /shared/exploit_done；IC 偵測 exploit_done 後會讓 blogic 處理 config.data。如果 /backdoor 成功執行，grading process 會記錄時間並終止；否則會產生 coredump 並執行 /triage，最多 60 rounds、30 分鐘。

3. Agent 執行流程

圖 3：Agent 閉環流程
本系統的核心不是單次 payload runner，而是具備狀態與回饋的 agent loop。每輪 /exploit 會根據 state.json 與 target_info.json 產生行動；若失敗，/triage 會觀察結果並更新下一輪策略。
Analyze：分析 /shared/blogic，取得 architecture、PIE/NX、symbol table、strings 與 gadgets。
Plan：根據 target_info.json 與 state.json 選擇模式與參數。
Generate：產生 /shared/config.data，建立 /shared/exploit_done。
Execute：IC 偵測 exploit_done 後執行 blogic。
Observe：判斷 success.txt、coredump 或 no_success_no_coredump。
Update State：/triage 更新 offset candidate、round、history 與 next_action。

5. 系統功能展示
5.1 Target Analyzer
Target Analyzer 是整個 agent 的 perception 層。它讓 agent 在產生 payload 前先理解目標程式，而不是直接寫死所有 exploit 參數。
自動尋找 target：/shared/blogic.copy 或 /shared/blogic。
判斷 ELF metadata：64-bit、x86_64、endianness、stripped。
判斷 PIE：透過 ELF Type 判斷 non-PIE。
判斷 NX/stack executable：解析 GNU_STACK 權限。
解析 symbol table：找出 execute_task、parse_config、maintenance_task、user_input 等。
掃描 strings 與 risky imports：如 config.data、user_input、memcpy、system。
尋找 ret gadgets：objdump -d 搜尋 ret instruction 並選出 preferred_ret。

5.2 Exploit Generator
/exploit 的角色是 action layer。它會先呼叫 analyzer，讀取 target_info.json，再根據 state.json 決定採用 fast final exploit 或 adaptive probing。
Payload layout: user_input = /backdoor\x00 + padding(offset_to_ret) + ret_gadget + execute_task 
Fast mode 中，offset 來自 calibrated lab profile 或 state；adaptive mode 中，offset 由 offset_candidates 逐輪嘗試。
5.3 Triage Feedback Module
/triage 是 feedback layer。它在 exploit 失敗後執行，觀察 success/coredump/no-success 結果，並更新下一輪策略。
success.txt 存在：標記 completed，停止。
coredump 存在：記錄 crash，若是 adaptive mode 則推進到下一個 offset candidate。
沒有 success 也沒有 coredump：記錄 no_success_no_coredump，同樣推進 offset candidate。
更新 state.json：round、last_result、offset_candidate_index、last_tried_offset、history。

8. 測試結果
8.1 Fast grading mode
Fast mode 是正式 grading 時的穩定路徑。在 fresh shared volume 中，不預先建立 adaptive state，因此 /exploit 預設走 final_exploit。三個 phase 均可 Round 1 成功。
Phase
條件
結果
說明
I Easy
ASLR disabled, stack executable, non-PIE
Round 1 success, 0 seconds
execute_task 與 ret gadget 固定，可直接成功。
II Medium
ASLR disabled, non-PIE
Round 1 success, 0 seconds
同樣使用固定 main binary code address。
III Hard
ASLR enabled, non-PIE
Round 1 success, 0 seconds
雖然 ASLR enabled，但 non-PIE 使 .text 位址固定。
Total time 顯示 0 seconds 是正常現象，因為 grader 以整數秒顯示時間；Round 1 成功時間少於 1 秒時就會顯示 0 seconds。30 分鐘是上限，不是目標執行時間。
8.2 Adaptive mode
Adaptive mode 用於展示 autonomous 行為。它不直接使用 calibrated offset，而是讓 agent 從候選清單中逐輪嘗試，依靠 /triage 更新 state。已測試 Phase I adaptive mode，Round 6 找到 offset 104 後成功。

Static offset inference 誤判 648
parse_config 是 C++ 程式，有許多 stack object；簡單選最大 rbp displacement 會選到 0x280，推成 648，導致 crash。

probe mode 可造成 crash，但 coredump 檔案內容為空，無法從 RIP/RSP 自動計算 offset。

作業看似允許 60 rounds / 30 minutes，但 fast mode 會 Round 1 成功。
說明 60 rounds/30 minutes 是上限；fast mode 是穩定 grading 路徑，adaptive mode 則展示自動探索。
10. 通用性與安全邊界
本系統的「通用」是指通用於作業提供的 bounded lab 類型，而不是可攻擊任意外部目標的泛用攻擊框架。此設計邊界很重要，因為作業環境明確限定 EC、IC 與 /shared 的互動。
只分析 /shared/blogic.copy 或 /shared/blogic。
只修改 /shared/config.data。
只建立 /shared/exploit_done 作為 IC 觸發訊號。
只讀取 /shared/coredump/*、success.txt、state.json 等 lab artifacts。
不進行網路掃描，不連接外部 host，不嘗試攻擊非 lab 服務。
11. 限制與未來工作
Static offset inference 對 C++ stack object 較脆弱，容易把 ifstream/string 物件誤判為 overflow buffer。
本地 coredump 為 0 bytes，因此無法實作標準 cyclic pattern + RIP extraction。
Fast mode 仍使用 calibrated lab profile 以確保 grading 穩定；adaptive mode 則用來展示自動找 offset 能力。
未來可加入更完整的 data-flow analysis、symbolic execution 或 gdb-based local crash inspection。
目前設計是 bounded lab agent，不是針對任意 binary 的完全泛用 exploit generator。

13. 結論
本專案完成一個受控 lab 環境中的 analysis-driven adaptive exploit agent。系統不只是寫入固定 payload，而是具備 target analysis、symbol discovery、ret gadget discovery、state management、triage feedback 與 adaptive offset probing。
在 fast mode 中，三個 phase 皆可 Round 1 成功；在 adaptive mode 中，agent 可於第 6 輪找到有效 offset 104 並觸發 /backdoor。整體符合作業對 /exploit、/triage、config.data、exploit_done、MaxRound 與 Phase I/II/III 的要求，同時也保留清楚的安全邊界與限制說明。
